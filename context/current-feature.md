## Goals
<!-- Goals and requirements -->

- `Screen — CV Template Picker`: header (title/subtitle) + filter chips (All/Modern/Classic/Minimal, filter-only, not sort) + a 2-row template grid (Single Column row, Two Column row; Aurora/Slate/Mono in each).
- Each card: mini CV preview thumbnail (styled per template family — Aurora/Modern indigo accents, Slate/Classic centered serif name, Mono/Minimal plain grayscale; Two Column adds a colored sidebar block), footer (template name, "{Variant} · {Family}" meta, Pro lock badge on every template except the free one), and a Use-template button.
- Lock badge + "Upgrade to Pro" tooltip on the 5 templates other than Aurora Single Column (the one free template per `project-overview.md`'s monetization table) — cards stay fully clickable/usable per the current dev-access rules (`00-general.md` Pro gating section).
- Selected-state treatment (2px accent border, "Selected" badge over the preview, filled indigo "Selected" button) applies identically whether this screen is reached fresh (creating a new CV) or via an existing CV's "Change template" action.
- Clicking a card's preview (not its button) opens an enlarged preview overlay (generic sample CV content, title = "{Name} — {Variant}", sub = "{Family} family") with its own "Use this template" button.
- Clicking "Use template"/"Use this template" on a template that isn't already selected: in the fresh-creation flow, applies immediately + toast ("Template applied to CV"); in the re-template flow (existing CV, reached with a `cvId`), first opens a confirm dialog ("Switch to {template}? Your content will be re-arranged into this layout. Nothing is deleted...") with Cancel/Continue, applying + toasting only on Continue.
- Dashboard's "Change template" action (`CvActionsMenu` → `DashboardView.handleChangeTemplate`) navigates here with the CV's id instead of showing a stub toast.

This feature makes the route itself support a fresh/no-`cvId` mode (defaults selection to the free template), reachable directly by URL, but does **not** add a UI entry point for it — only flow (b) ("Change template" from an existing CV) gets a real trigger, per this task's scope. Flagging this as the next gap rather than inventing a job-post-picker out of scope.
- The re-template "can't fit content" edge case from the spec isn't really checkable yet — there's no CV rendering/layout engine (`project-overview.md` Next Steps item 11) to detect overflow against. The confirm dialog's copy already covers the safe case ("nothing is deleted, you can switch back"); no overflow-detection logic was added.
- Extracted the Sidebar/Topbar/search-index/notifications derivation that used to live inline in `src/app/page.tsx` into `src/lib/app-shell-data.ts` (`getAppShellData()`) so this new route doesn't duplicate that logic — `page.tsx` (Dashboard) now just calls it too. Pure refactor, no behavior change.
- Added `TemplateFamily` to `src/types/cv.ts` and `src/lib/constants/cv-templates.ts` (`FREE_TEMPLATE_ID`, `TEMPLATE_FAMILY` name→family map) rather than storing family/free-ness on the mock `CVTemplate` fixtures — it's a fixed 1:1 mapping off the template name, not per-row data.
- Next.js 16 / React 19, Turbopack is the default for `dev` and `build`.
- Per `AGENTS.md`: this is a modified Next.js — consult `node_modules/next/dist/docs/` before writing framework code.
